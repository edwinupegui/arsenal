# Arsenal v3.0.0 — "Today" Cross-Domain View

Released: 2026-06-11

Arsenal evolves from a single-domain resource manager (v2) into a **local-first personal cockpit** that aggregates Resources and Todos into a unified daily-driver view.

## What's new

### Today view (the killer feature)

A new `internal/today/` package implements a **Provider registry pattern** that aggregates cross-domain data into a single dashboard.

- **4 sections in fixed order**: Overdue → Due Today → Upcoming → Recent Resources
- **Density cap** of 5 items per section with "show all" links
- **Provider interface** (`Name() + Sections(ctx)`) with graceful degradation — a failing provider does not break the page
- **2 shipped providers**:
  - `TodosProvider` — overdue, due-today, and upcoming todos (excludes done and soft-deleted)
  - `ResourcesProvider` — 5 most recent resources
- **Empty state** renderer with surface-specific hints (TUI vs web)
- **Default landing surface** changed from Resources to Today (configurable via `KeyLandingSurface`)

### TUI

- `areaToday` is now functional (no longer a placeholder) with `r` (refresh) and `n` (jump to new-todo) keybindings
- Area-switcher: `Tab`/`Shift+Tab` cycle, `1`–`5` direct jump
- Context-aware status bar with area-specific hints

### Web

- New `GET /today` route rendering sectioned cards
- Sidebar "Today" entry with **overdue count badge** that updates via HTMX `hx-swap-oob` after mark-done/open
- `commonPage()` isolation — Today aggregation does not run on non-Today pages

### CLI

- New `arsenal today` command — terminal surface for the cross-domain Today view
- Renders overdue / due-today / upcoming todos and recent resources as a tab-aligned table
- `show all` links point to the web routes when sections overflow the 5-item density cap
- `--json` flag for machine-readable output suitable for piping into other tools

### Todos end-to-end (phase 2)

- **CLI**: `arsenal todo add|list|show|edit|done|rm|restore|purge`
- **TUI**: full todos sub-model with list, detail, search, and actions
- **Web**: 11 HTMX routes wired with sidebar integration
- **Lifecycle**: add, edit, mark done, soft-delete, restore, hard-delete
- **Listing & search**: filter by status, priority, tags; full-text search via SQLite FTS5
- **Tags**: assign and filter; validates shared `domain.WithTags` helper
- **Recurrence**: metadata-only placeholder (auto-expansion deferred to v3.x)

### Shared foundations (phase 1.5)

- `domain.WithTags` — generic attacher helper for tag-based relations
- `Attacher` interface — encapsulates upsert-tag + attach + optional prune-orphans
- Typed config catalog — `KeyLandingSurface` and friends with `EnumValues` validation

## Breaking changes

- **`KeyLandingSurface` enum values changed**: `["tui", "web"]` → `["today", "resources"]`. Users with old config values fall back to the new default (`today`) silently. No data migration required. Config store validates on read.

## Known limitations

- **Timezone handling**: `date('now')` in SQLite is UTC. Due-today comparison may be off by hours for non-UTC users. Separate ADR planned for v3.0.1.
- **TUI new-todo form**: `n` key in `areaToday` switches to `areaTodos` (no inline form yet). Follow-up in v3.x.

## Architecture highlights

- **One SQLite database** for all domains (resources, todos, future finance, future calendar)
- **Provider registry** (ADR-0002 Change 4): cross-domain aggregation via independent providers with graceful degradation. Future Finance and Calendar providers plug in without registry changes.
- **Shared domain helpers** (`domain.WithTags`, `Attacher`) used by all domains
- **Strict TDD**: tests written before implementation for all new packages

## Upgrade notes

1. Pull the latest `main`
2. Existing config files with `KeyLandingSurface=tui` or `=web` will silently fall back to `today`. To preserve the v2 landing behavior, set `KeyLandingSurface=resources` in your config.
3. No database migration is required — the new `todos` table is created automatically on first run.
4. Optional: set `KeyLandingSurface=resources` if you prefer the v2 default landing.
