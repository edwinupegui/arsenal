# Design: phase-2-todos — Todos End-to-End

## Goals & Non-Goals

**Goals:**
- Deliver 9 capabilities (lifecycle, status, listing, search, tags, CLI, TUI, web, recurrence-placeholder) across 3 surfaces.
- Validate the shared-domain helpers (`domain.WithTags`, `sqliteutil.WithTx`) with a second domain.
- Prototype the TUI area-switcher with all 5 areas wired (functional: Resources + Todos; placeholder: Today/Finance/Calendar).
- Follow the existing `resources.Service` pattern: sqlc queries → service → CLI/TUI/web.

**Non-Goals:**
- Cross-domain search UNION ALL (phase 3).
- Today view aggregation (phase 3).
- Auto-expansion of recurring todos (v3.x).
- Finance/Calendar domain code (v3.x).
- Daemon, notifications, reminders.
- New migration file (the existing `20260608000002_todos.sql` is the contract).
- Unified FTS5 virtual table (per-domain FTS5 only; UNION is phase 3).
- Bulk operations or import/export for todos.

## Architecture Overview

Todos is the second domain in the four-domain v3.0 model. It shares the same SQLite database, `tags`/`categories` tables, and infrastructure (`sqliteutil.WithTx`, FTS5 helpers) already proven by resources. The `internal/todos/` package mirrors `internal/resources/`: a `Service` struct with methods for Create/Get/Update/MarkDone/MarkOpen/SoftDelete/Restore/Purge/List, backed by sqlc-generated queries in `internal/store/queries/todos.sql`.

Tags attach via the existing `domain.WithTags` helper using a todo-specific `Attacher` adapter. The `resources.Attacher.DeleteOrphanTags` already covers `todo_tags` in its UNION, so no duplicate pruning pass is needed. FTS5 helpers (`buildFTSQuery`/`stripFTSSpecials`) are package-level in `store/search.go` and reused directly by the new `SearchTodos` method in the same package. The TUI area-switcher adds a `currentArea` enum to `App` with `Tab`/`Shift+Tab` cycling and `1`-`5` direct jump; all five areas are wired, with Today/Finance/Calendar as `(coming soon)` placeholders.

## Key Contracts

### `internal/todos` package

```go
package todos

type Priority string
const (
    PriorityLow  Priority = "low"
    PriorityMed  Priority = "med"
    PriorityHigh Priority = "high"
)

type Status string
const (
    StatusOpen Status = "open"
    StatusDone Status = "done"
)

type Recurrence string
const (
    RecurrenceNone    Recurrence = "none"
    RecurrenceDaily   Recurrence = "daily"
    RecurrenceWeekly  Recurrence = "weekly"
    RecurrenceMonthly Recurrence = "monthly"
)

type CreateInput struct {
    Title       string
    Description string
    Priority    Priority
    DueDate     *string
    CategoryID  *int64
    Notes       string
    Recurrence  Recurrence
    Tags        []string
}

type ListFilter struct {
    CategorySlug string
    TagName      string
    Status       Status
    Priority     Priority
    OnlyOverdue  bool
    DueBefore    string
    Trashed      bool
    Limit        int
    Offset       int
    Search       string // FTS5 query; when set, delegates to SearchTodos
}

type Service struct { db *sql.DB; q *store.Queries }
func New(db *sql.DB) *Service
func (s *Service) Create(ctx context.Context, in CreateInput) (*store.Todo, error)
func (s *Service) Get(ctx context.Context, id int64) (*store.Todo, error)
func (s *Service) Update(ctx context.Context, id int64, in CreateInput) (*store.Todo, error)
func (s *Service) MarkDone(ctx context.Context, id int64) error
func (s *Service) MarkOpen(ctx context.Context, id int64) error
func (s *Service) SoftDelete(ctx context.Context, id int64) error
func (s *Service) Restore(ctx context.Context, id int64) error
func (s *Service) Purge(ctx context.Context, id int64) error
func (s *Service) List(ctx context.Context, f ListFilter) ([]*store.Todo, error)
```

All `CreateInput` fields except `Title` are optional; defaults match the migration DDL. Priorities/Status/Recurrence have `Valid()` and `String()` methods plus `All*()` slices.

### sqlc queries (16 total)

| Query | SQL contract |
|-------|-------------|
| `CreateTodo` | INSERT with RETURNING * |
| `GetTodo` | SELECT by id; no soft-delete filter (caller decides) |
| `ListTodos` | Dynamic WHERE builder with all ListFilter fields; ORDER BY `due_date ASC NULLS LAST, created_at DESC, id DESC`; LIMIT/OFFSET |
| `ListTrashedTodos` | Only `deleted_at IS NOT NULL`; sort by `deleted_at DESC` |
| `UpdateTodo` | UPDATE all mutable fields; RETURNING *; `updated_at` bumped by trigger |
| `SoftDeleteTodo` | SET `deleted_at = now()` WHERE `id = ? AND deleted_at IS NULL` |
| `RestoreTodo` | SET `deleted_at = NULL` WHERE `id = ? AND deleted_at IS NOT NULL` |
| `PurgeTodo` | DELETE by id; cascade removes `todo_tags` and FTS5 entry |
| `MarkTodoDone` | SET `status = 'done', done_at = now()` WHERE `id = ? AND status = 'open'` — idempotent |
| `MarkTodoOpen` | SET `status = 'open', done_at = NULL` WHERE `id = ? AND status = 'done'` — idempotent |
| `ListTodosByStatus` | Filtered by status; used internally by List when no other filters |
| `ListTodosDueBefore` | `due_date < ? AND status = 'open' AND due_date IS NOT NULL` |
| `ListTodosDueBetween` | For future "this week" views in phase 3 |
| `CountOpenTodos` | COUNT(*) WHERE status='open' AND deleted_at IS NULL |
| `ListTodosFiltered` | Dynamic builder (category JOIN, tag JOIN, status, priority, overdue, trashed) |
| `SearchTodos` | FTS5 MATCH on `todos_fts` JOIN `todos` + tags CSV; excludes `deleted_at IS NOT NULL` |

### `domain.WithTags` reuse

**Decision: new `internal/todos/attacher.go`** (mirror of `resources/attacher.go`, ~40 lines). It implements `domain.Attacher` with `todo_id`-scoped `AttachTagToOwner`. `DeleteOrphanTags` is shared — the resources attacher already covers `todo_tags` in its UNION (line 46 in `resources/attacher.go`). The todo attacher does NOT need its own prune call; when `WithTags` is called with `PruneOrphans=true`, it delegates to the resources attacher's `DeleteOrphanTags` which already covers both domains.

**Alternative considered**: Generic attacher in `internal/domain/`. Rejected because the 40-line adapter is minimal overhead and keeps the domain boundary explicit — no need for generics at this scale.

### FTS5 helpers

**Decision: no extraction needed.** `buildFTSQuery` and `stripFTSSpecials` are package-level in `internal/store/search.go`. The new `SearchTodos` method lives in the same `store` package and calls them directly. No new file.

## Data Model

The `todos` table (already on disk in `20260608000002_todos.sql`):
- **Columns**: `id`, `title`, `description`, `priority` (low/med/high), `status` (open/done), `due_date` (ISO date, nullable), `category_id` (FK → categories), `notes`, `recurrence` (none/daily/weekly/monthly), `done_at`, `created_at`, `updated_at`, `deleted_at`.
- **Indexes**: `idx_todos_due`, `idx_todos_status`, `idx_todos_deleted`, `idx_todos_priority`, `idx_todo_tags_tag`.
- **`todo_tags`**: M:N junction with `ON DELETE CASCADE` on both FKs.
- **`todos_fts`**: FTS5 virtual table on `title, description, notes, tags` (tokenize=`unicode61 remove_diacritics 2`).
- **`v_todo_tags`**: Aggregating view (GROUP_CONCAT tag names per todo).
- **5 sync triggers**: insert/update/delete on `todos` + insert/delete on `todo_tags` keep `todos_fts` in sync.

Rowid-mapping: triggers use `todos.id` as `todos_fts.rowid` — same strategy as resources. No new mapping table needed.

## Sequence Diagrams

### Create todo with tags
```
CLI/TUI/Web
    → todos.Service.Create(CreateInput)
        → domain.ValidateTitle(title)
        → domain.NormalizeTags(tags)
        → sqliteutil.WithTx(db, func(tx) {
            q := s.q.WithTx(tx)
            → q.CreateTodo(params)          // sqlc: INSERT INTO todos ... RETURNING *
            → att := todos.NewAttacher(q)
            → domain.WithTags(ctx, db, tx, att, AttachInput{
                OwnerKind: "todo", OwnerID: row.ID, Tags: tags, PruneOrphans: false
              })
                → att.UpsertTag → att.AttachTagToOwner
            → return nil → commit
          })
    → return *store.Todo
```

### Mark done (idempotent)
```
CLI/TUI/Web
    → todos.Service.MarkDone(id)
        → q.MarkTodoDone(id)                // sqlc: UPDATE todos SET status='done', done_at=now()
                                             //       WHERE id=? AND status='open'
        → return nil                        // no-op if already done — zero rows updated, no error
    → success
```

### FTS5 search
```
TUI search box / CLI search
    → todos.Service.List(ListFilter{Search: "pag"})
        → q.SearchTodos(ctx, query, limit)  // store/search.go
            → match := buildFTSQuery("pag") // → `"pag"*`
            → SELECT r.*, (tags CSV), snippet(todos_fts,2,'<m>','</m>'), rank
              FROM todos_fts f
              JOIN todos r ON r.id = f.rowid
              LEFT JOIN categories c ON c.id = r.category_id
              WHERE todos_fts MATCH ? AND r.deleted_at IS NULL
              ORDER BY rank LIMIT ?
    → return []*store.Todo (with snippet/score in result shape)
```

## Test Strategy (Strict TDD)

**Mandatory** (must pass before PR merges):
- `internal/todos/service_test.go` — mirrors `internal/resources/service_test.go`:
  - Create happy path + tag dedup/normalization
  - Validation: empty title, bad priority, bad recurrence, title > 500 chars
  - SoftDelete/Restore cycle
  - MarkDone idempotency (done→done no-op)
  - MarkOpen idempotency (open→open no-op)
  - Update replaces tags and prunes orphans
  - FTS5 search after tag attach
  - Rollback on validation failure (no row inserted)
  - Purge after soft-delete removes row + cascade
  - List with status/priority/overdue/category/tag filters

**Optional** (can defer, not blocking):
- `internal/cli/todo_test.go` — Cobra command integration tests
- `internal/tui/todos_test.go` — teatest or direct Update() tests
- `internal/web/todos_test.go` — httptest handler tests

Pattern: `newTestDB(t)` from resources test (open temp DB + migrate → close on Cleanup). Table-driven with `t.Run`.

## Migration & Rollout

- **No new migration**: `20260608000002_todos.sql` is on disk and will be applied by existing `store.Migrate` on next `arsenal` invocation.
- **Rollout path**: branch deploy → `make build` → `go test ./...` (green) → manual CLI smoke (`add`, `list`, `done`, `rm`, `restore`, `purge --yes`) → manual TUI smoke (`Tab` switch, list, mark done) → manual web smoke (`/todos`, create, mark done via HTMX) → merge.
- No data migration required (tables are empty until this PR lands).

## Risks & Open Questions

- **Review workload**: 9 capabilities × 3 surfaces + service + tests ≈ 1200+ lines. **400-line budget risk: High.** The `ask-on-risk` delivery strategy from preflight should apply — the orchestrator must decide whether to chain/split PRs. Service + tests alone are ~600 lines.
- **TUI area-switcher scope creep**: The placeholder wiring touches `app.go` significantly. If this alone exceeds 200 lines, consider a separate PR slice (service+CLI first, TUI second, web third).
- **Q2 (default TUI landing)**: Resolved as `areaResources` for now (preserves existing behavior). Tunable via `configstore` in v3.x.
- **Q3 (area-switching keys)**: Resolved as Tab/Shift+Tab + 1-5. Tunable by user.
- **Attacher dependency**: The todos attacher reuses `resources.Attacher.DeleteOrphanTags` because it already covers `todo_tags` in its UNION. If the resources attacher is refactored later, the todos attacher must follow suit. Low risk.
